# Pony 整站模板验收标准入口

**现行版本：[v2：工具优先、全元素布局](TEMPLATE_ACCEPTANCE_STANDARD_V2.md)**（2026-09-19）。用户最新要求：每次分配独立确认；不跑版涵盖所有标签/元素；工具优先，AI只处理工具未覆盖或无法确定的项目。v2替代下方v1中无条件逐页AI复核的方式，并提高矩阵与组件门槛。以下v1保留为历史，不单独作为当前放行标准。

## 历史 v1

生效：2026-09-18。来源：用户对“逐页完成响应式、交互、SEO及代码检查后交付”的明确确认。本标准用于以后每一套由 Pony 制作或提交的整站模板；每周四套须**逐套**通过，不以四套合计或首页通过代替。范围与更详细的测试方法沿用业务仓库 `AGENTS.md`、本工作流 `PRD.md`、`docs/ACCEPTANCE.md`、`docs/ACCEPTANCE_INCREMENT.md`；当次用户要求可以增加检查项。团队审查、合并、上线及搜索引擎收录另记状态。

## 1. 页面与数据范围

从真实路由、模板继承/include、实际数据契约列出该套全部可访问页面类型、代表 URL 与依赖。首页、列表、详情、搜索及实际存在的资讯/联赛/球队等页面均进入计划；include/宏在其宿主页面验收。缺样例、后端数据不可得或路由失败的页面保留为 `blocked`，不得从分母移除或标 `pass`。每套记录目标编号、Git SHA/工作树状态、预览环境、输入哈希、页面清单。

## 2. 响应式与视觉

- 每个实际页面类型运行 Chromium 360、390、768、1280、1920 CSS px × light/dark；390与1280另查无 JS。关键页增查320、899/900断点两侧、200%文字，以及WebKit/Firefox 390与1280双主题；实际CSS断点另补两侧。完整矩阵以当次页面契约和 `plan-acceptance` 输出为准。
- 逐页检查整页横向溢出、遮挡、错位、截断、内容不可读、导航和主操作不可达；赛事页加入比分0/空值、状态、长队名、三位比分、logo失败等适用数据状态。不能靠隐藏内容或只检查首屏使结果通过。
- 至少逐页审阅390和1280、light/dark的截图与渲染后DOM，记录页面、视口、主题、证据与修复结果。自动截图成功只算采集成功，AI须实际看图；主题颜色方案须证明页面实际生效。

## 3. 交互与功能

在真实本地应用中检查并留证：搜索从输入/回车/按钮到结果、空结果及可用详情链接；主题切换、刷新和跨页保持；手机导航打开/关闭、键盘与焦点；长页回顶；实际存在的筛选和分页。验证相关脚本/资源加载、手机APP下载入口及jQuery先于ajs.js。无 JS 时主要内容和可用链接仍应可访问；确有 JS 专用功能须按确认的契约解释。不能以按钮存在、事件绑定或外部夹具通过代替真实链路。后端未提供能力时标 `blocked` 并写明所需接口/数据。

## 4. SEO

以每个代表 URL 的**原始HTTP响应及实际渲染HTML**为证据检查：title/description/keywords与当前配置绑定并与页面内容一致，标题层级和主要内容清晰，重要内链可达，图片alt合适，canonical/robots/分页/搜索页策略符合已确认契约，JSON-LD语法和内容事实一致，没有测试文案或空壳占位。动态内容与 HeaderJS/FooterJS 保留原有语义。未确认的索引策略标 `needs_review`，不自行设关键词密度、字数或排名阈值。本地SEO通过不代表Bing已收录或排名。

## 5. 代码与变更边界

检查目标模板内 Jinja 可解析并在真实应用逐页渲染；JS无导致关键功能失效的异常；新增资源路径和跨模板依赖有效；数据绑定、比分0与空值、转义、链接、图片回退符合实际契约。运行本次变更相关的现有测试/检查器及 `git diff --check`，记录命令和结果。核对只改获分配的 `templates/<id>/`、`static/<id>/`；不改 Python/后端、共享资源、其他模板或环境文件，不夹带凭据/夹具/假数据。保留已有工作树改动，提交时仅纳入本套授权文件。

## 6. 判定与交付记录

每项结果只用 `pass / fail / blocked / needs_review / not_applicable`；`pass`须有当前输入版本的证据，`not_applicable`须有理由。P0/P1故障（例如页面500、主要内容/比分错误、关键交互失效、严重手机溢出或SEO索引错误）修复并重新跑受影响页面及完整交付矩阵；P2列明。页面缺样本、契约未确认、未看图、未执行的检查均不能算通过。

一套模板只有在页面契约确认、完整矩阵和必要数据状态检查完成、实际交互与SEO检查完成、逐页AI复核完成、相关代码检查通过、无未解决P0/P1且最终范围无越界时，才标记 **`ready_for_human_review`** 并提交主管验收。现有 `assess-acceptance` 可检出部分证据和覆盖缺口；代码边界、真实交互、SEO语义及主管决定还需按本标准逐项记录，不能仅凭工具退出码宣称通过。主管接受、合并、部署、Bing抓取分别记录，不自动从本地结果推导。

每套交付附：页面/URL清单、矩阵及失败记录、截图/DOM/HTTP证据索引、交互记录、SEO结论、代码检查命令和结果、设计差异、未解决项及责任层、Git提交/推送状态。四套各有独立记录。
