## 最小复用方式

沿用 Python/Jinja 及外部工作流，不引入前端框架、组件发布平台或新的构建系统。参考库保留源码路径与版本；经验证的功能在制作时放进目标模板自己的宏、组件、CSS、JS目录。目标模板可独立提交，不依赖其他模板私有文件。

| 组件/能力 | 当前参考入口 | 入库前检查 |
|---|---|---|
| 页面框架、TDK、动态注入与APP脚本 | `templates/r62/master.html`；`templates/x66/master.html`–`x80/master.html` | 保留动态变量、HeaderJS/FooterJS及既有safe语义，jQuery在ajs.js之前；逐页实际输出验证 |
| 比分与队徽 | `templates/x80/macros/match_score.html` | 明确比分0、空值、取消/未赛、长队名、三位比分契约；移除x80私有路径依赖；检查图片失败不会循环回退 |
| 赛事行与链接 | `templates/x80/index.html` 内 `match_urls` / `match_row` 宏 | 不照搬字段兜底；按目标页面真实上下文确认大小写字段、热赛/普通赛链接 |
| 分页 | `templates/x80/widgets/pagination.html` | 保留真实路由、参数及空态；无JS可访问 |
| 联赛、队伍、资讯、侧栏 | `templates/x80/widgets/`、`templates/x80/sidebar.html` | 当前页面确实有数据；不是所有页面均可直接include |
| 主题、搜索表单、手机导航、回顶 | 外部 `src/generate.py` 的现有草稿实现 | 仅候选，现有editorial/rail未完成整站验收；真实搜索受后端能力约束 |
| 验收机制 | `src/audit.py`、`src/acceptance.py`、`src/browser_checks.py`、`config/rules.json` | 复用既有工具，执行与人工/AI看图分别记录；规则存在不等于全部实现 |

每个实际抽取的组件记录：来源模板/路径/哈希、页面上下文、输入字段与空态、宏/include依赖、资源和交互依赖、主题/响应式、测试证据、已使用的目标模板。状态由 `candidate_unverified` 经专项检查到 `verified_for_contract`；通过只对记录的契约/版本有效，源文件变化需重验。

## 每周四套如何拉开差异

先看本地 x66–x80，实际开发时补相同内容、同视口、同主题的浏览器对照，不能只读标题就声称视觉不同。保留历史交付设计规格，和已交付的Pony模板比较。

本轮人工阅读的源码例子：x66首页有hero/streams区域与赛事分类tabs；x70分热门、今日、明日直播并include侧栏；x72含资讯、录像、视频、集锦、标签和赛程区域；x75以热门/全部赛事组织主区并include侧栏；x78含足球录像、联赛阵容、赛事、视频资讯及侧栏；x80有match_row/match_urls宏和热门赛事、赛事直播、最新资讯、球星/联赛模块。标题和include只是结构线索，不能据此认定视觉差异或数据完整。全部15套索引见 `catalog/source-inventory/X66-X80.md`。

以下是首批可选设计方向，属于AI方案，不是已完成模板或团队分配编号：

| 方向 | 导航与首页组织 | 赛事/资讯 | 详情与移动端 |
|---|---|---|---|
| 体育编辑台 | 横向报头，焦点内容后接赛程与资讯 | 清晰分栏，资讯图文列表 | 正文主栏+辅助栏，手机按主次合流 |
| 赛事控制台 | 桌面侧边导航，赛程为主 | 紧凑赛事行，辅助资讯面板 | 比赛信息居中，移动抽屉导航 |
| 联赛日程册 | 顶部紧凑导航，按已提供分组展示 | 时间线/分组赛程，简洁资讯索引 | 比赛摘要后分段展开，手机单列 |
| 运动杂志 | 大字号品牌区，模块化卡片 | 宽卡与小卡层级，独立资讯区 | 文章阅读优先，移动大触控区 |

选择方向以真实页面数据能力为前提，缺数据就调整布局或记录后端依赖。至少三个主要布局维度可指认不同，是沿用PRD的内部预检标准，不是Sit的硬性数字；只换色、圆角、字体或类名不足。组件逻辑可复用，结构设计和视觉语言要有差异；每套内部各页面保持一致。

## 每次制作和交付

1. 刷新源码目录，读最新指令/聊天、Git状态与历史Pony交付记录；确认团队分配的四个模板编号。编号未知时仅做外部设计和草稿，不占用业务编号。
2. 从索引选组件候选，以 `src/audit.py` 核对目标参考模板的路由、字段、继承和资源契约，不假设所有模板兼容。
3. 每套保存design-brief/design-spec、页面清单及差异说明；先做首页、代表列表、详情，再扩展全站。
4. 写入范围仅目标 `templates/<id>/` 与 `static/<id>/`。不改Python、后端、共享代码、其他模板或.env；不添加伪数据/假搜索。后端缺项记录给用户协调Rechard。
5. 执行既有逐页明暗主题、手机/平板/桌面、无JS及极端数据检查；实测搜索、菜单、回顶、主题记忆、资源加载、APP入口。逐页AI看图并留证，不把生成截图等于看图通过。
6. 按PRD第9章检查实际渲染HTML中的TDK、主内容、标题层级、链接、canonical、robots与结构化数据真实性；检查分页/搜索页策略。后端/部署问题单列。代码规范按本项目AGENTS与现有Jinja约定执行，检查变更边界与diff。
7. 记录每套编号、来源、设计差异、组件版本、全页验收结果、未解决问题、提交/推送/主管验收状态。按当次授权完成提交；本轮建库不触发公司提交、推送、上线。

验收输出区分 pass/fail/blocked/needs_review。当前源码索引全为source_only；SEO检查不等于收录或排名保证。制作四套的数量目标不能替代每套的完整验收。
