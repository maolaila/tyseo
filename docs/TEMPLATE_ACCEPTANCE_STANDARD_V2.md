生效2026-09-19，依据用户本轮加严要求。替代v1的执行方式，保留公司边界、逐页覆盖、证据与最终人审。引用WCAG作为工程依据，不宣称已取得完整WCAG认证，也不代表模板已通过公司验收。

## 1. 范围随每次任务分配

- 每套使用独立TaskSpec：task_id、target_template_id、分配来源与确认时间、模式、可写目录、页面范围、预览地址、Git SHA、输入hash。每周重核编号，不继承上周授权。
- 当前z1–z17只属于这次任务，记录在 `tasks/ad-hoc.json`；`z_*.py`是本次适配器。其他编号用已有通用 `workflow.py --task ...` 与新TaskSpec，不改本标准、不自动解禁其他目录。
- 维护模式 `page_scope=existing_only` 只检查本套实际存在的入口/组件。缺文件候选有理由地排除，不要求补建；已有页面缺样例、缺数据、HTTP错误仍为blocked。现有页指向不存在页面的失效链接仍算问题。新模板按确认交付清单，不能套此选项删减范围。
- 检查范围不扩大修改权限。只修样式的任务，SEO/后端疑点独立记录；不能据本标准自行改接口、加业务功能或改生产文案。业务仍限当次 `templates/{id}`、`static/{id}`。
- URL以真实链接/确认路由为准，探索样例另列；线上须核实实际模板资源编号。历史上站表、Cloudflare challenge、本地500和生产500分别记录。

## 2. 全元素“不跑版”门槛

### 政策2.2：必须拦截的实际功能与布局回归

来源：2026-09-19 Leo 报告 z16 球队筛选点击无反应、详情关联赛程Logo意外掉行；用户要求写入硬门槛，并明确**对齐方式由具体样式决定，页面被挤占后跑版才是硬门槛**。

- `FILTER-RESULT-SET` / `filter_results`：每个存在筛选的页面或标签页都必须以实际数据条件计算期望的可见行ID集合，再真实点击控件并比对浏览器可见集合。验证每个单条件、条件组合、切换顺序、恢复全部、无匹配结果及日期分组的显示。相同条数但不同ID也必须检查；只验证active颜色、checked、事件触发、inline style或截图均不算通过。特别覆盖样式中的 `display: ... !important` 对隐藏逻辑的影响。已支持筛选却无效/显示错误结果为P1，不可交付。
- `LAYOUT-INTEGRITY` / `layout_integrity`：按照该组件在各断点的真实设计约束验证边界、布局槽位和可操作性。内容增加/容器变窄/长队名或标题/三位数比分/空或失败图片后，不能出现非预期掉行、元素挤占、相互重叠、关键文字被裁切、操作被遮挡。合法的上下结构、左右结构、表格局部滚动、装饰叠层不能统一判错；**不得全局强制Logo/队名/比分同一行或同一中心线**。未明确的组件设计记录needs_review，不能默认PASS。
- 组件规则必须覆盖所有实际宿主页，包括球队资料页的非默认标签、独立赛程、比赛详情中的主客队关联列表；首页测试通过不替代内页。真实数据与外部夹具分开记录。无接口/无样例为blocked；N/A必须证明该页面没有该模块。
- 两项均进入 `config/acceptance-policy.json` 的必需证据键；`assess-acceptance` 对漏项、失败、旧政策及证据失效拒绝放行。回归必须包含能重现旧缺陷的失败对照，避免测试只复述修复实现。旧2.1报告不升级为2.2通过。

本次可重复入口：`python src/z16_leo_regression.py --output runs/<新的验收目录>`（使用外部虚拟环境和 Playwright CLI 0.1.20，默认真实预览6316）。输出原始HTTP、筛选前提与期望/实际ID、逐行几何、截图、反例结果和文件哈希；命令失败或source_fresh为false不得放行。覆盖球队资料“比赛”标签、独立赛程、详情关联赛程，并分别标记真实数据和夹具。此适配器的961px桌面五列、手机三列规则只属于当前z16；其他模板必须绑定各自真实布局与页面，不能照搬这个对齐断言。

同一入口支持 `--browser chrome|firefox|webkit`，每个引擎使用独立的新run目录。换机安装入口同时安装CLI自己的Firefox/WebKit包并实际启动，详见 `docs/MIGRATION.md`；浏览器缺失是blocked，不能记作已经测过。

### 政策2.3：逐页链接与操作效果硬门槛

来源：2026-09-19 用户发现此前只测首页基础交互及 z16 专项，要求在验收工具中增加所有现有页面的功能测试。每次任务的页面清单从当前真实模板/路由契约产生，不能把某次 z1–z17 的编号写成通用范围。

- `LINK-NAVIGATION` / `link_navigation`：逐页读取原始 HTML 的全部内部 `a[href]`，按模板与目标去重检查实际 HTTP 状态，404/5xx/错误跳转不得通过；对首页、栏目、列表、详情、分页等关键链路再用浏览器实际点击，核对最终 URL、状态与目标内容。空链接、伪链接、锚点缺失须单独报告。外部链接、弹窗/下载和站点注入链接明确分类，未测不能计通过。本地后端 500、共享页面及路由缺陷注明责任层，不跨业务仓库边界修复。
- `ACTION-EFFECT` / `action_effect`：逐页列出可见按钮、选项、标签、筛选、搜索、主题、菜单和回顶，实际点击/选择，并按各自契约检查结果集、URL、可见内容、开关状态或滚动位置。仅按钮存在、事件触发、样式高亮或不报 JS 错误不足以证明功能可用；有数据前提/后端依赖时保留前提和失败证据。脚本先覆盖确定性效果，无法确定效果的控件点击后记 needs_review 并提供逐页控件清单，不能无证据记 N/A。
- 对带数据面板的标签，逐个验证被选中标签对应的可见内容或明确空态，并验证随标签变化的详情/更多链接。原始响应无数据时不得保留上一标签的内容、伪造排名或仅改变高亮；要记录真实字段来源和缺数据责任层。2026-09-20 z16 `/zuqiu` 积分榜标签曾只变高亮，榜单与“更多”未同步，专项复现和回归入口见 `docs/Z16_FOOTBALL_STANDINGS_TABS_20260920.md`。这项专项通过不代表其他页面交互已全量通过。
- 当前 z1–z17 外部执行入口先运行 `python src/z_link_audit.py --output runs/<新HTTP目录>`，然后运行 `python src/z_page_actions.py --input runs/<新HTTP目录> --output runs/<新浏览器目录>`；后者通过 Playwright CLI 0.1.20 使用每套独立 session，在390/1280 CSS px逐页执行。第一步负责原始响应、全部内部链接目标及控件清单；第二步逐页点击代表性导航、搜索按钮与Enter，并操作可判定控件。`--max-pages` 仅供开发试跑，实际覆盖未执行的页面必须保留未测状态。过滤结果的精确 ID、中文特殊词/空结果/分页及复杂业务控件仍以相应专项断言证明，普通 DOM 变化不能替代。两类证据都要按当次源码和政策版本重新生成。网络检查不是浏览器点击，点击通过也不能替代原始响应；只做首页功能测试不能声称全页通过。两项是 `config/acceptance-policy.json` 2.3 的必需证据键，缺测、失败及旧政策结果不得放行。
- 页面多、单次CLI可能超时的模板改用 `python src/z_page_actions_chunks.py --input runs/<新HTTP目录> --output runs/<新分片目录> --id <编号>`。它按页面分片运行同一点击脚本并核对 `(页面,390/1280)` 完整集合，不能因超时删页或把分片结果冒充全套PASS；每个分片仍保留单独证据。

### 政策2.4：滚动表格表头与交互后布局硬门槛

来源：2026-09-20 用户在 z16 首页指出积分榜滚动数据行透过表头、表头文字受挤压；要求以后将此类跑版与各类交互效果纳入验收。`scroll_table_header_integrity` 是所有实际使用局部滚动表格的页面必需证据项；没有这种组件才可附 DOM/契约依据记不适用。旧2.3结果不自动升格。

- 表头在列表顶、中、底的局部滚动状态必须完整可读，数据行不能覆盖表头文字或从半透明 sticky 表头透出；表头的命中层级、实际背景不透明度、单元格文字是否被挤成异常多行与裁切均须核查。允许设计明确的局部横向滚动，不允许整页横向溢出或用 `overflow:hidden` 掩盖信息。
- `scripts/layout-audit.js` 对可见且确实有内部纵向滚动的 sticky 表格暂时滚动并恢复原位置；若行与表头相交、表头背景透出或被其他元素挡住，出 P1，疑似异常换行入 needs_review。组件结构无法自动判定、外部 iframe 或非 sticky 设计须记录能力边界；工具未发现不能直接声称视觉没有问题。
- 每个实际宿主页仍按现行尺寸、明暗主题和数据状态逐页检查；切换筛选/标签/分页或改变表格内容后必须复查表头与数据区，并断言结果集及点击目标发生了契约规定的变化。截图是复核证据，不能代替几何、层级和实际操作结果。
- z16 本次专项入口与截图证据见 `docs/Z16_PORTAL_STICKY_HEADER_20260920.md`；此局部修复通过不等于 z1–z17 按政策2.4全量通过，之前2.3报告保持历史状态。

- 全程使用日常字号与100%浏览器缩放；不执行刻意200%字体、强制字距/行距、200%–400%浏览器缩放验收。

## 4. SEO与交互

逐页分别存原始HTTP状态/头/HTML、JS后DOM、无JSDOM，不能用page.content冒充HTTP。工具先检查正文/主标题/导航/分页发现入口、动态TDK绑定与转义、多页及多配置变化、空字段与错误继承、语言/标题结构、真实内链、alt、JSON-LD语法/真实字段、已有robots/Sitemap和索引契约。保留keywords、HeaderJS/FooterJS、jQuery/ajs.js。不发明关键词密度、字数或文本/HTML比例阈值。

事实语义、未知canonical/索引策略、schema适用性与隐藏内容疑点只在工具无法确认时交AI。默认一个清楚H1是工程约定，不直接将多个H1说成不收录；无某类schema不自动失败；搜索页合法noindex保留。生产canonical和本地地址分开。SEO通过不证明Bing已抓取/收录/排名。

搜索实测输入/Enter/按钮/中文特殊字符/空值/空结果/详情/实际分页；主题跨页刷新；菜单开关、Escape、焦点与滚动恢复；回顶、分页筛选和APP横幅按真实契约。后端/第三方依赖记录责任层，不前端造数。

## 5. 工具优先流水线与放行

1. 核对当次分配、初始树、真实页面/组件/数据契约，输出范围及排除依据。
2. 工具跑HTTP/SEO、源码/绑定、浏览器矩阵、组件几何/碰撞/命中/媒体/CLS；完整证据落盘、终端只输出失败摘要。
3. 使用pass/fail/blocked/needs_review/not_applicable；缺测/不支持不pass。每项含rule_id、页面URL、尺寸主题数据状态、选择器/相关组件、期望实际、严重度、责任层、版本/hash与证据路径。
4. 明确失败在允许目录修复，复跑相关页及公共组件所有宿主页；具体合法叠层例外保留理由与原发现，不能放宽全局断言。
5. **只有工具无法判断/覆盖的项目进入AI队列**。AI读取针对性DOM、原图和上下文；不重复工具已经完整确定的检查。可重复的新模式优先沉淀为工具用例。
6. 最终按完整计划核对覆盖；源码/配置/数据/规则版本变化使相关旧证据失效。缩范围只接受明确分配变更，并保留历史。
7. 所有适用项有当前证据，无未解决P0/P1、无未决契约/能力缺口、范围正确后才 `ready_for_human_review`。AI处理项与工具解决项分列；公司人审/合并/部署/Bing独立记账。

`assess-acceptance`要求每个用例的checks覆盖政策全部检查类，逐项标tool/ai/human方法、verifier及证据文件/hash；N/A有理由与依据。工具完整解决的复核槽跳过AI；工具未执行、漏检查和明确失败先回工具工作队列，只有明确的歧义/能力缺口才进AI队列。只填“AI看过”、存在截图或进程退出0都不能放行；判定器只核对提交的证据，不补造检查结果。
