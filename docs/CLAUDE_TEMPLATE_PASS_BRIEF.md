## 二之二、遇到 404 / 500 先分清是谁的问题（2026-09-21 下午主管 Leo 和后端 Rechard 的最新说法）

- Rechard："咱们所有模版调用的后端数据，都是一样的，只是不同的模版，展示方式不同"；"没有对应的模版页，就要加一下"（参考其他模板做）。Leo："你404也是要問Rechard，有時候是你參數根本不對，他那邊路由沒辦法匹配"；"有時候本地資料跟生產不同，老闆已生產為準"；"主要頁面都還是要檢查"。
- 所以每个 404 / 500 都要先查原因，不能一律甩给后端：
  1. **500**：预览是 Flask debug 模式，报错页里有异常类型和完整堆栈。`TemplateNotFound: zN/xxx.html` = 这套模板缺这个页面 → **前端要补**：看 `run.py` 里这个路由传了哪些变量，参考其他模板族（`templates/x70`、`templates/r62`、`templates/a10` 等同名文件）的做法，用本模板自己的风格做一页。堆栈最后一帧落在 `templates/zN/…` 里（`UndefinedError`、模板里取下标/调方法出错）= 模板写法问题 → **前端修**。堆栈落在 `run.py`、`cache/` 等 Python 代码里 = 后端问题 → 按第三节报告。
  2. **404**：先对照 `run.py` 的 `@app.route` 和其他模板族同一处链接的写法，看是不是本模板把地址/参数拼错了（大小写、缺 `.html`、联赛拼音不对、分页格式不对）→ 拼错了就**前端修**；地址没错而路由确实不存在或数据没有 → 按第三节报告。
  3. **已查明的一个共性问题，不用再花时间查**：所有模板的 `/tags/<id>`（以及 `/tag/<id>.html`）本地都是 500，原因在后端：`run.py` 的 `tag_list` 里 `recovery_id_offset(id)`（`cache/cache_data.py`）在站点 `OffsetNum` 为空/0 时把 URL 里的字符串 id 原样返回，随后 `recovery_id <= 0` 抛 `TypeError: '<=' not supported between instances of 'str' and 'int'`。模板侧改不了，链接写法（`/tags/{{ item.id }}`）和其他模板族一致、没有错。报告里照第三节的格式写一条并配一张图即可。

## 三、不是前端能修的问题怎么办

后端路由 404、接口或页面 500、数据缺失这类，你只能改模板和静态文件，修不了的**不要在模板里绕过、隐藏或造假数据**（例外：某个入口在这套数据下注定是死链，而模板可以合理地不渲染这个入口时，可以按条件不渲染，但必须在报告里写明）。把它写进报告的"需要后端处理"一节。负责人会拿这份清单去找后端，所以**每一条都要具体到别人能照着复现**（负责人 2026-09-21 定的反馈标准）：

- 哪套模板、**在哪个页面**（完整地址，如 `http://127.0.0.1:6302/CBA/luxiang/709789.html`）；
- **点了哪个按钮或链接**（写出它在页面上的位置和文字，如"正文下方『相关标签』里的『篮球』"）；
- **目标路径是什么**、返回 404 还是 500；500 的写出报错类型和出错位置（如 `IndexError: list index out of range`，`run.py` 第几行哪个函数），是接口就写接口地址和怎么触发的；
- 线上同一路径是否同样出错（能查就查，查不了写"未查"）；
- **配图**：截一张出问题的页面，把要点的那个按钮或链接用醒目的框圈出来（可以在截图前用 `playwright-cli … eval` 给该元素临时加 `outline: 3px solid #22c55e; outline-offset: 4px` 再截图——只是在浏览器里临时加，不要写进模板），再截一张点过去之后的报错页。图片存到你的 `runs/` 目录，报告里写出图片的完整路径。

只写"某模板有 404""有几个链接打不开"这种笼统的话不合格。
