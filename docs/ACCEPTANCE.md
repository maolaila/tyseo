# 验收、失败用例与需求追踪

后续Pony整站模板的固定交付判定见 [TEMPLATE_ACCEPTANCE_STANDARD.md](TEMPLATE_ACCEPTANCE_STANDARD.md)。本文件继续作为细项与失败用例清单。

本文是PRD的执行清单；测试需要Codex实现并在真实本地项目运行。本包只提供规范，未执行以下业务测试。

## 1. 团队要求映射

| 团队事实/要求 | PRD位置 | 实施后必须出现的证据 |
|---|---|---|
| 一套完整站，约十几个页面 | §1、§4 | 实际页面/路由清单；不可只数HTML文件。 |
| 每套样式/排版不同 | §5 | 设计蓝图及与r62/最近模板对比；不只换色。 |
| 只能改两个目录、不改后端 | §3 | 写入前检查、工作树基线、增量文件清单。 |
| RWD | §7.1、§10 | 所有页面的默认视口矩阵与溢出/遮挡结果。 |
| dark/light | §7.2 | 每页两主题、刷新跨页持久化、存储失败回退。 |
| search | §7.3 | 真实路由/参数依据，输入到结果和详情的链路记录。 |
| goto top | §7.4 | 长页滚动和返回顶部、手机无遮挡记录。 |
| 手机drawer/popover导航 | §7.5 | 打开/关闭/导航/断点/焦点与无JS回退。 |
| 每页检查、不能严重错版 | §8、§10 | 逐页证据索引、AI复核记录、人工待检列表。 |
| AI检查SEO | §9 | 原始HTML、链接、head、截图、规则ID与明确结论。 |
| 保留两步域名流程 | §2 | 域名文件无改动；无表格写入、采购、发布副作用。 |

## 2. 检查器自身的失败用例

至少实现下列可复现测试；测试夹具只在外部工具目录，不故意破坏公司源码。每条包含“正常样本应通过”和“异常样本应被检出”，避免检查器无论输入如何都返回PASS。

| ID | 注入的问题 | 预期 |
|---|---|---|
| F01 | 计划写入run.py、requirements或.env | 写入前拒绝；保护现有文件。 |
| F02 | 目标新模板任务试图改r62/别人的模板 | 拒绝，不能通过扩大白名单解决。 |
| F03 | 路径含../、符号链接或Windows junction逃逸 | 解析真实路径后拒绝。 |
| F04 | 工作区已有用户改动 | 记录基线，不覆盖/清理、不归入本任务提交。 |
| F05 | 新模板编号已存在或尚未确认 | 阻止业务生成；允许继续外部工具/草稿。 |
| F06 | 新模板引用r62私有CSS/JS/父模板 | 检出跨模板依赖，不能默默沿用。 |
| F07 | 包含文件被误算成页面，遗漏真实详情路由 | 页面发现/覆盖检查失败。 |
| F08 | 必需Jinja变量拼错但渲染为空 | 契约检查失败，不能以HTTP 200通过。 |
| F09 | 用假值兜底让0分显示横线 | 比分语义断言失败。 |
| F10 | null比分被伪造成0:0 | 待赛/缺失状态断言失败。 |
| F11 | 主客队/比分绑定反了 | 数据与可见文本映射失败。 |
| F12 | 118:115或长队名让比分挤出手机屏幕 | 组件布局+截图复核失败。 |
| F13 | logo失败后布局坍塌或无限重试 | 图像失败测试失败。 |
| F14 | 深色模式输入框/比分文字看不见 | 主题与视觉检查失败。 |
| F15 | 本地存储抛错导致页面JS初始化中止 | 存储异常回退测试失败。 |
| F16 | 搜索按钮不提交或使用虚构路由 | 功能契约与真实链路失败。 |
| F17 | 本页筛选被报告为全站搜索 | 能力范围检查失败或needs_review，不PASS。 |
| F18 | 手机drawer关闭后body仍不可滚动 | 交互回归失败。 |
| F19 | 模态导航Tab逃逸/关闭焦点丢失 | 对应模态交互测试失败。 |
| F20 | goto top遮住分页或比分 | 手机关键区域遮挡测试失败。 |
| F21 | 初始HTML空壳，只有JS补齐内容 | 原始响应与无JS检查失败。 |
| F22 | 新闻/赛事链接只有onclick，没有真实href | 链接发现检查失败。 |
| F23 | 分页内容变化却全指向首页canonical | 按已核验的分页政策报冲突，不能一律自改后端。 |
| F24 | canonical残留演示域名或其他站点域名 | URL/站点配置检查失败。 |
| F25 | 应可索引页meta/header误带noindex | 失败；报告是模板还是后端问题。 |
| F26 | 合法不索引的搜索页含noindex | 按契约不误报，不移除该策略。 |
| F27 | 所有详情页都继承首页TDK | head差异与绑定检查失败。 |
| F28 | 测试队名/品牌/假作者混入交付 | 生产夹具隔离检查失败。 |
| F29 | 只改配色、DOM类名却声称新布局 | 设计差异needs_review/不满足，不自动认可。 |
| F30 | 把比分区域mask掉再通过截图 | 检出关键区域被屏蔽，测试无效。 |
| F31 | 只测首页却输出“全套通过” | 覆盖分母和页面清单核对失败。 |
| F32 | 缺截图、命令或原始响应的PASS记录 | 证据结构检查失败。 |
| F33 | 模拟数据通过被写成真实应用通过 | 环境分类检查失败。 |
| F34 | 旧PASS在代码/契约改变后被直接沿用 | 版本/哈希失效，重跑相关阶段。 |
| F35 | 本地完成后触发表格写入/采购/发布 | 权限/流程边界测试失败。 |
| F36 | 遇到后端限制时修改Python强行通过 | 拒绝；输出backend dependency。 |
| F37 | 伪装Bingbot的自有请求算成真实抓取 | 来源与环境校验失败。 |
| F38 | 自动修复为了通过而删除测试/扩大容差 | 修复审计失败，不更新成功状态。 |

## 3. 全套完成判定

必须给出总页面类型数、实际执行数量、失败/阻断/N/A数量和证据，不能只给百分比。

- 工具自己的校验/门禁/恢复执行测试通过。
- 全部必需页面已实现；所有适用团队功能都有证据。
- 所有新引入P0/P1已修复，或明确保持阻断不标可交付。
- 分别给出fixture与real_app结果；未实机联调不得“完成实际模板验收”。
- 页面逐一截图和AI复核；人工验收保持独立状态。
- 文件增量严格在目标两个业务目录；秘密、夹具、报告不进入业务包。
- 已有域名工作流与首批记录未改动，没有触发后续流程。
- 模板差异报告可查看；不把内部相似度算法当主管或Bing判定。
